# Sicherheitsrichtlinie

## Geltungsbereich

Diese Richtlinie gilt für alle Repositories der GitHub-Organisation [artaker](https://github.com/artaker), einschließlich privater Projekte (interne Entwicklung, Kundenprojekte, Lieferanten-Kollaboration).

## Schwachstellen melden

Bitte melden Sie Sicherheitslücken **nicht** über öffentliche Issues oder Pull Requests.

**Kontakt:** [compliance@artaker.it](mailto:compliance@artaker.it)

**Verantwortlich:** Raphael Kury (Security Officer)

### Was wir von Ihnen erwarten

- Beschreibung der Schwachstelle und betroffener Komponenten/Repository
- Schritte zur Reproduktion (Proof of Concept, falls vorhanden)
- Einschätzung der Auswirkungen (Vertraulichkeit, Integrität, Verfügbarkeit)
- Ihre Kontaktdaten für Rückfragen

### Was Sie von uns erwarten

- Bestätigung des Eingangs in angemessener Frist (in der Regel innerhalb von 5 Werktagen)
- Koordinierte Behebung und Abstimmung zur Offenlegung (responsible disclosure)
- Keine rechtlichen Schritte bei good-faith-Meldungen, sofern Sie die Richtlinie einhalten

## GitHub Security Advisories

Für Repositories mit aktivierten Security Advisories können gemeldete Schwachstellen über [GitHub Security Advisories](https://docs.github.com/de/code-security/security-advisories) koordiniert bearbeitet und veröffentlicht werden — auch in **privaten** Repositories.

## Keine öffentlichen Repositories ohne Freigabe

Neue öffentliche Repositories oder die Sichtbarkeit „public“ erfordern eine ausdrückliche Freigabe durch Org-Owner. Siehe [ARTAKER.md](ARTAKER.md).
