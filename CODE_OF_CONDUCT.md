# Verhaltenskodex (GitHub)

## Geltungsbereich

Dieser Hinweis gilt für alle Mitglieder und Kollaboratoren mit Zugang zur GitHub-Organisation [artaker](https://github.com/artaker) und zu zugehörigen Repositories.

Die Nutzung von GitHub bei Artaker erfolgt im Rahmen unserer **internen, verbindlichen Richtlinien**. Die vollständigen Fassungen werden **nicht** in diesem Repository gepflegt — maßgeblich sind stets die aktuellen Dokumente im Unternehmen.

## Verbindliche Richtlinien

| Thema | Was gilt auf GitHub (Kurzfassung) | Ansprechpartner |
|-------|-----------------------------------|-----------------|
| **KI-Richtlinie** | Nutzung von KI-Tools, Code und Daten nur gemäß der aktuellen internen KI-Richtlinie | **Christian Semrajc** (HR) |
| **DSGVO / Datenschutz** | Keine personenbezogenen oder kundenspezifischen Daten in Issues, PRs, Commits oder öffentlichen Repo-Inhalten ohne Freigabe; Speicherfristen und Löschung nach DSGVO-Richtlinie | **Christian Semrajc** (HR) |
| **Kundenverträge** | Vertraulichkeit, IP und Nutzungsrechte aus Kunden- und Lieferantenverträgen — besonders bei Kundenprojekt-Repos; keine Weitergabe von Kundencode oder -daten außerhalb der vereinbarten Grenzen | **Christian Semrajc** (HR) |

Fragen zu den **aktuellen Fassungen** dieser Richtlinien und zu deren Auslegung richten Sie an **Christian Semrajc**, nicht an dieses Repository.

## Ergänzend auf GitHub

- Professioneller, respektvoller Umgang in Issues, PRs und Kommentaren
- Sicherheitsvorfälle: [SECURITY.md](SECURITY.md) → [compliance@artaker.it](mailto:compliance@artaker.it) (nicht als normales Issue)
- Org-Regeln: [ARTAKER.md](ARTAKER.md)

## Meldungen

Verstöße gegen Richtlinien, unangemessenes Verhalten oder Unsicherheit bei der Einordnung:

1. **Christian Semrajc** (HR) — Richtlinien KI, DSGVO, Kundenverträge, Verhalten am Arbeitsplatz  
2. **[compliance@artaker.it](mailto:compliance@artaker.it)** — bei sicherheits- oder compliance-relevanten Vorfällen (ggf. gemeinsam mit HR)

Org-Owner können bei schwerwiegenden Verstößen zusätzlich Repository- oder Org-Zugang entziehen.
